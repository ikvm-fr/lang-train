# lang-train

A browser-based pronunciation trainer: a phrase plays → a pause for you to repeat it → the next phrase.
Runs entirely in the frontend (PWA), including with the screen off.

- Player: https://ikvm-fr.github.io/lang-train/
- Editor: https://ikvm-fr.github.io/lang-train/editor/
- Branch previews: `https://ikvm-fr.github.io/lang-train/preview/<branch>/` (and `.../editor/`; `/` in a branch name becomes `-`)

## Repository layout

```
apps/player/     the trainer (mobile PWA), served at /
apps/editor/     the markup editor (desktop), served at /editor/
packages/pack/   pack format: types, reader, writer (shared by both apps)
packages/i18n/   localization runtime and shared strings
docs/            specifications
scripts/         demo pack generator, site assembly
```

## Development

npm workspaces; run everything from the repository root.

```bash
npm install
npm run dev:player     # player dev server
npm run dev:editor     # editor dev server
npm run typecheck      # all workspaces
npm test               # unit tests
npm run build          # builds both apps and assembles the site in dist/
```

Deployment is handled by [.github/workflows/pages.yml](.github/workflows/pages.yml): every push is built and
published to the `gh-pages` branch. GitHub Pages must be set to serve `gh-pages` / `(root)`.

## Localization

Both apps are available in English (source), German, Polish, Russian, French and Chinese (Simplified).
The language follows the browser on first start, can be switched at any time without reloading
(player: start screen and *General settings*; editor: header), and the choice is shared by both apps.

- `packages/i18n`: a small runtime (`{placeholders}`, plurals via `Intl.PluralRules`, locale number/date formatting)
  and strings shared by both apps (pack errors, default field names).
- `apps/*/src/i18n/<lang>.ts`: app dictionaries. `en.ts` is the source of truth; every other language is typed
  against it, so a missing or extra key fails the type check. Tests also check plural forms and placeholders.
- Errors carry a code (`CodedError` in `packages/pack`) and are translated in the UI as `err.<code>`.
- To add a language: add it to `LANGS`/`LANG_NAMES`/`LOCALES` in `packages/i18n/src/core.ts`, then add a
  dictionary file next to each `en.ts` and register it in the corresponding `index.ts`.

User data is never translated: pack titles, phrase texts and field names. A new editor project gets its default
field names in the current interface language.

## Pack format

A pack is a ZIP with `pack.json` (metadata and the field model), `phrases.csv` and MP3 clips.
The full specification is [docs/pack-format.md](docs/pack-format.md); the reader and writer live in
`packages/pack` (`npm test` runs its tests). The player also still opens prototype packs without `pack.json`.

Example: `apps/player/public/demo/demo.zip`, generated by `scripts/make-demo-pack.sh` (espeak-ng + ffmpeg).

## How playback works

`apps/player/src/engine/Player.ts` is a React-independent engine. Phrases and pauses are scheduled ahead of time on the
`AudioContext` timeline (~30 s ahead), so timers throttled in the background cannot break the pauses.
The media session keeps the app alive in the background (either a silent `<audio>` track alongside, or
routing the output through an `<audio>` stream; switchable in the settings for testing).

Headset / notification buttons: ⏯ pause, ⏭ next phrase, ⏮ one more repeat of the current phrase.
